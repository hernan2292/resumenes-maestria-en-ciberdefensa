Tensión de Diseño Criptográfico

Confidencialidad IND-CPA vs. Utilidad de Búsqueda

Diapo 2/9

Para que un algoritmo simétrico sea seguro bajo estándares modernos, debe cumplir con **IND-CPA** (indistinguibilidad bajo ataque de texto plano elegido):

  • Cifrado Probabilístico: AES en modos GCM o CBC requiere un IV aleatorio. Mismo texto plano genera textos cifrados totalmente distintos.
  • Pérdida de Estructura: El servidor en la nube no puede indexar, ordenar ni buscar palabras clave directamente.
  • Alternativa Ingenua: Cifrado Determinista (mismo IV siempre) permite buscar, pero filtra frecuencias y es vulnerable a criptoanálisis básico.

Preliminares Simétricos

Derivación de Claves por PRF (HMAC-SHA256)

Diapo 3/9

El esquema SSE aísla las funciones y el acceso a los datos derivando claves independientes a partir de una única clave maestra privada ($K$):

  • PRF (Función Pseudoaleatoria): Genera salidas deterministas pero indistinguibles de ruido para agentes externos. Instanciada con HMAC-SHA256:
HMAC_K(w) = H((K ^ opad) || H((K ^ ipad) || w))
  • Aislamiento de Llaves:
    • $K_1$: Derivación de direcciones hash.
    • $K_2$: Derivación de llaves de máscara de listas.
    • $K_3$: Cifrado de documentos (AES-GCM).

Cifrado de Documentos

Confidencialidad IND-CPA con AES-256-GCM

Diapo 4/9

Los archivos de logs o telemetría se cifran en el cliente de manera probabilística antes de subirse al servidor externo:

  • AES-GCM (Galois/Counter Mode): Proporciona cifrado simétrico y verificación de integridad (AEAD).
  • Galois Field $\mathbb{GF}(2^{128})$: Genera un tag de autenticación de 128 bits para asegurar que el log no haya sido alterado.
  • Estructura del Registro: El archivo cifrado final se sube como:
    Registro = IV || Ciphertext || AuthTag

Estructuración del Registro del Índice

Generación de Nodos Cifrados con AES

Diapo 5/9

Para permitir búsquedas eficientes en tiempo sublineal $O(t)$, el índice se estructura mediante listas enlazadas cifradas ocultas en una tabla hash desordenada:

  • Carga Útil del Nodo ($P_j$): Contiene el ID del documento y la dirección física del siguiente nodo de la lista:
    P_j = id_j || Addr_{j+1}
  • Cifrado Simétrico AES: El cliente genera una clave de lista $K_w = \operatorname{PRF}(K_2, w)$ para la palabra $w$ y cifra la carga útil:
    V_j = AES-CBC-Enc_{K_w}(IV, id_j || Addr_{j+1})

Algoritmo BuildIndex

Direccionamiento Ciego en Tabla Hash

Diapo 6/9

El cliente dispersa los nodos cifrados en una tabla hash desordenada en el servidor para evitar que el host relacione secuencias:

  • Dirección del Primer Nodo: Es predecible por el cliente mediante la clave $K_1$:
    Addr_1 = HMAC_{K_1}(w)
  • Direcciones de Nodos Intermedios: Se generan de forma aleatoria. Los nodos se suben desordenados.
  • Seguridad del Servidor: A ojos del host externo, la tabla hash almacena bloques de datos cifrados en posiciones aleatorias, indistinguibles de ruido.

Algoritmo Search

Recorrido y Descifrado Ciego en el Servidor

Diapo 7/9

Para realizar una consulta sobre la palabra $w$, el cliente genera el Trapdoor dual $T_w = (\operatorname{Addr}_1, K_w)$ y el servidor ejecuta el recorrido:

  1. Accede a la dirección inicial $\operatorname{Addr}_1$ en la tabla hash.
  2. Usa la clave $K_w$ para descifrar el nodo con AES.
  3. Obtiene el ID del documento y la dirección del siguiente nodo $\operatorname{Addr}_2$.
  4. Salta a $\operatorname{Addr}_2$, descifra, y repite hasta encontrar `NULL`.

Complejidad Óptima: $O(t)$ donde $t$ es el número de coincidencias, independiente del tamaño de la base de datos.

Mitigación de Fugas en Dominio Simétrico

Padding de Bloques AES y Técnicas Anti-Fuga

Diapo 8/9

Para evitar ataques de inyección y reconstrucción de volumen que analizan los patrones del servidor, el cliente implementa:

  • Padding de Documentos: Se rellenan los syslogs a tamaño fijo con PKCS#7 antes de aplicar AES-GCM.
  • Padding de Índice (Volume Padding): Se insertan registros ficticios (*dummies*) para que todas las palabras parezcan tener igual cantidad de nodos devueltos.
  • ORAM (Oblivious RAM): Baraja y recifra bloques de memoria tras cada acceso para eliminar el patrón de acceso.

Conclusión del Análisis

Caso de Uso SOC: Telemetría Zero Trust

Diapo 9/9

La implementación técnica de AES en esquemas de búsqueda simétrica es viable y de alto rendimiento para centros de operaciones modernos (SOC):

  • Los syslog se indexan, cifran localmente con AES y se almacenan de forma inmutable en la nube o Blockchain.
  • El analista realiza búsquedas ciegas de indicadores de compromiso (IoCs) en milisegundos.
  • El proveedor de almacenamiento distribuidor no aprende qué amenazas se están investigando ni lee logs de auditoría.
Ecosistema SOC Cifrado
Analista SOC: Genera Trapdoor con Kw.
Nube: Descifra nodos AES en O(t) milisegundos.
Blockchain: Garantiza inmutabilidad de los índices.
Resultado: Privacidad y cumplimiento total.
La soberanía y control del cifrado reside exclusivamente en las llaves del cliente.
